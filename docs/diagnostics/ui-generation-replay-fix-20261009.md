## 修复范围

1. 数据库详情 ID、元素 ID、动作类型从步骤序列化，经 Node 回放，传递到成功、失败及异常路径的执行记录。合成导航明确标记且没有数据库步骤 ID。
2. 诊断优先使用真实数据库引用，并核对当前用例、项目、动作类型和元素。旧记录只在完整已执行操作前缀唯一匹配时兼容反查；不能确定时不选择其他元素。
3. 自动修复的导航、URL、等待及定位器修改都限制在机器证据确认的失败详情。定位器修复克隆元素，仅重连失败详情；同组其他动作与复用该元素的断言不随之修改。修复前再次锁定并核对失败详情。
4. 页面步骤增加 authentication_mode，默认 auto。auto 仅协调已确认的同账号独立登录组：首组导航到配置的登录路由、两项凭据填写、一次提交、并有登录后的 URL 断言时，使用环境认证并保留原成功断言。账号不同、流程混合或后续登录不会被自动省略，而是明确提示配置认证方式。
5. environment 模式只允许认证成功断言，支持环境自动登录或明确绑定的角色登录态。script 模式保留显式认证步骤，并关闭该用例的环境预登录与快照注入，由脚本负责登录/角色切换。两种显式模式不能在同一用例混用。密码变量仍按既有机制处理，本次未新增秘密解析或把已脱敏密码还原入库。
6. 多个角色登录态的自动模式继续逐组切换，不再普遍过滤登录导航。每组优先使用实际配置页面 URL，不再一律替换成环境首页。含显式首导航的组不再插入额外前置导航。
7. 页面步骤编辑界面提供认证方式选择；生成内容保存和复制步骤均保留该配置。生成提示补充认证与角色切换约束。

修复不包含工单系统 URL、账号、菜单或 placeholder 的硬编码。登录协调使用当前环境配置与观察到的动作证据；修改密码等业务操作不因出现密码框就被当作登录跳过。
