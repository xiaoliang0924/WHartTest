# UI 用例后台生成修复（2026-10-02）

## 问题与结果

用例 1173 的功能执行已经通过，但生成和回放仍运行在页面的 SSE 请求内；离开页面会取消请求，导致既没有绑定 UI 用例，也没有生成失败说明。

现在功能通过后先持久化生成任务，再交给 Celery 执行。网页不再承担生成或验证任务的生命周期。结果保存在原功能执行记录中，功能结果和 UI 生成结果分别展示。

## 行为

1. 持久化排队、生成中、验证中、成功、失败、停止中和已停止状态；打开报告或刷新对话时重新读取状态。
2. 使用原执行用户、项目、模型配置及会话检查点生成，合并最后一步尚未归并到检查点的工具证据。执行用户失效、项目权限撤销或证据缺失时明确失败。
3. 后台回放独立创建浏览器，不要求网页 WebSocket 在线；仍复用现有登录配置、步骤执行、截图、Trace 和失败诊断。
4. 失败后可使用已有执行记录重试生成；重试不会重新执行功能测试，但会回放生成的 UI 用例进行验证。
5. 同一功能用例的提交通过数据库锁和 Redis 锁防止重复生成、回放；重复队列投递不会再次执行。旧任务无法覆盖重试任务结果。
6. 显式停止会取消工作，等待浏览器清理完成，再开放重试。页面关闭和刷新不会发送停止请求。
7. 模型生成阶段上限 180 秒；任务默认总时限 900 秒，可通过 UI_GENERATION_JOB_TIMEOUT_SECONDS 配置在 60–1500 秒之间。排队额外预留 300 秒。定时核对处理失联或超时任务，报告查询也会核对状态。
8. 任务按项目隔离；仅原执行用户或超级管理员可停止、重试，并同时受项目权限检查约束。队列消息只含执行记录 ID 和任务 ID。

- 其中真实 Chromium 回放通过，验证无网页连接时仍保存执行记录；浏览器仅访问隔离 data URL 测试页面。
- 验证请求取消后的任务交接、重复提交和投递、并发状态变化、停止清理、超时、原会话证据和工具作用域恢复、用户失效、项目范围隔离。
- 数据库迁移 0040 成功应用；makemigrations --check --dry-run 无缺失迁移。
- 前端 vue-tsc 类型检查、Vite 生产构建通过；本地检查六种状态的文本、按钮和排版。
- 未重跑生产建单用例，未调用生产业务接口。

## 上线要求

本次为本地代码改动，尚未推送 Gitea 或部署生产。

需要发布 Django 和 Vue 改动，执行数据库迁移，并确保 Celery worker、Celery beat 与后端加载同一版本。后台 worker 必须具有现有 Recorder 的 Node、Playwright、Chromium 运行依赖及媒体目录权限。当前部署的后端镜像已经包含这些依赖，隔离测试复用了该镜像。

升级后可在结果抽屉或对话中，对有完整检查点的历史失败记录使用“使用执行记录重试生成”。旧记录的功能通过状态不会被改成 UI 生成成功；没有执行证据时会明确失败。
